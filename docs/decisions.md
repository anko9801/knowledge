# 決めたことと、決めていないこと

**このリポジトリは複数のセッションが同時に触る。** 2026-08-21 には push が
非 fast-forward で 5 回弾かれ、同じ連載を別々の判断で削る、という取り違えも起きた。

`docs/build.md` は**仕組みの説明**で、ここは**判断の記録**である。
なぜそう決めたか、そしてまだ決めていないことを置く。
コミットメッセージにしか無い理由は、探せないので消えたのと同じになる。

書くときは日付を付ける。撤回したものは消さず、取り消し線ではなく
「撤回」の節へ移して理由を残す。同じ議論を二度しないためにある。

## 決めていないこと

**決める前に、ここを読んでほしい。** 片方だけ直すと食い違う。

### λ 計算と Curry–Howard をどちらの連載の正典にするか

`lambda-calculus` / `simply-typed-lambda` / `curry-howard` を、
形式意味論 第 1 回（`linguistics/semantics/1`）が `provides` している。
いっぽう `cs/types`（型と計算）も同じ範囲を扱う予定で立っている。

概念グラフは複数の記事が同じ概念を provide してよい（経路の選択肢になる）ので
壊れないが、本文が二重になる。どちらかを正典にして、もう片方から参照するのが自然。

**cs 側を正典にするのが筋だと思う。** 形式意味論は λ 計算を道具として
使う側で、型理論そのものを主題にしていない。ただし cs/types をまだ書いていないので、
書く人が決めてよい。

### すぐそこを指す参照には、中身を添えない（2026-08-23）

peek を添える理由は往復コスト（分割注意）である。だから**読んだばかりのものには
理由が無い**。実際、記事内の参照 621 件のうち 61 件は直前の主張をその場で受けていた。

```
@def:matrix を読むと、行列の掛け算があの定義である理由も出てくる   ← 2 行上
@thm:cartan は、それが d と ι だけで書けることを言っている        ← 3 行上
```

判定は**本体との隔たり**で、`peek.ts` の `NEAR`。本体の中は数えないので、
長い定理でもすぐ下から指せば添わない。前方参照（「次の定理」を先に名指しする）も
同じ物差しで測る。

**HTML の文字数では測れない。** MathML は画面では小さいのに生の HTML では
巨大なので、数式を一つ挟んだだけで「遠い」に化ける。88 本を組んで実測すると、
`.typ` の 14 行差が 74 文字、5 行差が 407 文字と、**順序が入れ替わっていた。**

そこで**タグと数式を落とした本文の字数**で測る（`readingLength`）。これなら分離する。

| 本文 100 字で切ると | |
| --- | --- |
| 直後を受けている 61 件のうち | **54 件が落ちる** |
| 残る 7 件 | 間に段落が挟まっている。添えてよい側 |
| 行距離では遠いが本文は近い 10 件 | 間が数式だけ。**落として正しい** |

**88 本での実測：参照 623 件のうち 66 件（11%）が添わなくなった。**

`peek.test.ts` に境界を 4 本置いた（すぐそこ／数式を挟んでも本文で測る／
本体の長さに釣られない／前方参照）。**既存のテストは全部、本体の直後に

### 外の作り手と食い違った六点を決めた（2026-08-23）

88 本を測り直し、堀元見・水野太貴、謎解き公演の作り方、catnose のポストと
突き合わせた（[writing.md](writing.md)）。**そのまま借りられない点が六つ出たので、
一つずつ決める。** 借りない側も理由を残す。

**1. 結論は先に出す。ただし先に出すのは中謎まで。**

向こうは結論から話すのを意図的に避ける（読者が自分で組み立てる時間が気持ちいい）。
こちらは「答えを先に書く」節を置いている。**こちらを維持する。**
読み物は離脱コストがゼロなので、47 秒の側が効く。

ただし**冒頭で出すのは記事の主張であって、最後の飛躍ではない**。
ベクトル解析 1 が実際そうなっている——冒頭「演算子は一つしかない」、
中盤「磁場はベクトルではない」、末尾「Maxwell 方程式が 2 本になる」。
先に出したのは中謎までで、大謎は最後に残っている。この形を守る。

**2. 覚えてもらう側を維持する。**

向こうは「内容は全然覚えていない」を前提にしていて、テンポと関係性が商品である。
**こちらは借りられない。連載が依存グラフの上に乗っているからである。**
第 n 回が第 n−1 回を要求する構造で、覚えていないと連載が成立しない。
あちらは 1 本完結なので覚えなくてよい。**構造が違う。**

ただし想起の問いの**密度は上げない**。102 問で足りている
（数を目標にすると本文をなぞる問いが混ざる、と reader.md にある）。

**この一点だけは、サイトが何のためにあるかの判断なので、覆すなら本人が決めてよい。**

**3. peek は現状のまま。**（当初「記事内は切る」と決めたが、同日に撤回。下記）

謎解き側は大謎の材料を一度見せてから忘れさせるので、常に思い出させる peek とは
向きが逆に見えた。**が、実装を始める前に測ったら前提が間違っていた。**
撤回の理由は「撤回」の節に書いた。

**4. 「削った差分を見せる」二本立ては採らない。**

向こうは 4 時間半の統語論回をそのまま出し、別に 1 時間版を置く。
削った差分が「知的作業の痕跡」として面白い、という理屈である。

**記事では採らない。** 動画は見る側が版を選べて、長さ自体が視聴の単位になる。
記事で二版持つと保守が倍になり、同期がずれた瞬間にどちらも信用できなくなる。
分量の判断は「連載の分量は、中身で決める」（CLAUDE.md）で足りる。

**5. ちょけてよい。禁じるのは、自分を外したちょけだけ。**

reader.md は「権威を茶化す口調」を取らないと決めていたが、**根拠に挙げていた
「CLAUDE.md がキャラクターを禁じている」という規則は存在しなかった。**
残る理由（検索から来る専門家が同じページを見る）も外れていて、
自嘲は専門家にも刺さる。**見下しでなければ誰も撃たれない。**

線は「ちょけるかどうか」ではなく「**自分が入っているか**」に引く。

**6. 飛躍の担保を二つに分ける。**

reader.md は全部の飛躍に定理を要求していた。**これは数学の中の飛躍にだけ要る。**
1 形式と 2 形式の差は普通に生きていても分からないので、保証が要るからである。

**数学の外へ出る飛躍には、読者がすでに差を知っていることが担保になる。**
「公理は道具の設計仕様である」に定理は付いていないが、雑ではない。

**この区別を落としていたせいで、外への飛躍が制度的に書けなくなっていた。**
分野の中に閉じた書き出しが 26 本ある。書き手の癖ではなく、規則の副作用である。

### PDF も配る（2026-08-22）

paged 側に A4 の紙面まで用意しておきながら、一度も配っていなかった。

リンクが 404 になるので、そのときは `[order].astro` の `.pdf` も消す。

### docs は三つに分ける（2026-08-22）

`build.md` が 1204 行あって、フォントのサブセット手順と「なぜ隙間を先に開けるか」が

あちらは現時点の決めごとを一枚にまとめたもの。判断の理由をここに書き、

### 題名は替えず、概念名を足す（2026-08-22）

題名は異常を出す形にしてある（「穴が空いていないこと」「好きに選んだのに、
答えが整数になる」）。掴みには効くが、**何を学ぶ回なのかが題名から読めない**。
連載の一覧を眺めている読者と、検索から来た読者はそこで止まる。

題名を概念名に替えると掴みが消えるので、替えずに足した。
`provides` として既にデータにあるものを、記事の題名の下と分野の一覧に出す。
全部は出さない（多い回で 32 個）。記事で 6 件、一覧で 5 件、残りは数だけ。

### 数学の記事を、物理のために書かない（2026-08-20）

数学の連載で、物理を**導入**にも**到達点**にも置かない。本文中の例として一言だけ。

`taxonomy.ts` が math と physics を分野として分けている以上、数学の連載の
到達点が全部物理なら、その分割が嘘になる。実際、線形代数 4 の第 1 節が
「物理のテンソルはなぜどちらかに寄るのか」、Riemann 6 が記事まるごと
Einstein 方程式になっていた。

物理を外した穴には**数学側の payoff を入れる**。外して終わりにしない
（比較幾何、Mayer--Vietoris をそこに置いた）。逆向き——物理や化学の連載が
数学を前提にする——は正しい依存なので自由。

## 撤回

### オートマトンと形式手法の連載（2026-08-28 に足し、同日に外した）

**どちらも単独では立たなかった。**

オートマトンは 13 概念で足したが、生きるのは「有限の状態しか持てないと括弧が
数えられない」だけだった。**これは計算量理論の軸（モデルを絞ると限界が決まる）の
最も単純な例**なので、そちらへ 4 個だけ移した。正規言語の閉包、Myhill--Nerode、
構文解析まで並べると**言語論の教科書**になり、この repo の形ではなくなる。

形式手法は 13 概念のうち 7 個が**道具の内部**だった。CDCL がどう節を学習するかは、
x86 の MOV と同じで事例である。残した 6 個（遷移系、時相論理、安全性と活性、
モデル検査、状態爆発、双模倣）は並行と分散へ寄せた。既にある
`soundness-completeness-tradeoff`（停止する検査器は必ず近似になる）に対して、
**有限なら全部試せる → ただし有限でも指数で試し切れない**、という一本の線だけが
残る。落とした側：抽象解釈、記号表現、粗化と精緻化、分離論理、SAT、SMT、精製。

### 下界は計算量理論、アルゴリズムは作る側（2026-08-28）

「アルゴリズムと下界」を一つの連載で立てたが、**割り方が逆だった。**

| | |
| --- | --- |
| 計算量理論 | 「これ以上は無理」の側。決定木の下界、敵対者論法、通信計算量、空間下界、近似の限界、Chomsky 階層 |
| アルゴリズム | 届かせる側。分割統治と Master 定理、動的計画、貪欲とマトロイド、償却、乱択、LP と最大流、近似の構成 |

**同じ近似アルゴリズムでも、限界は前者、作り方は後者になる。** 計算量理論は
記事が 3 本あり、暗号理論 6 概念のうち 5 つがこれを要求しているので、
そもそも落とせない側でもあった。

### 関係理論の連載（2026-08-28 に足し、同日に外した）

関係モデル、関係代数、Codd の定理、書けない問い合わせ、関数従属、正規形、
Chase、直列化可能性、二相ロック、分離水準を 10 概念で足して、「関係理論 全 4 回」を
立てた。**同じ日に外した。**

**理由は、分かるようになるのが SQL の挙動だけだったこと。** 表現力の定理は
二本あって、Codd の定理（関係代数と一階述語論理は同じ表現力）と、推移閉包が
一階では書けないこと。どちらも本物の定理だが、**payoff が「SQL がなぜそう
動くか腑に落ちる」に閉じる**。計算量理論や情報理論の「そもそも何ができないか」
とは、届く範囲が違った。

**3 概念だけ残した。** 直列化可能性・二相ロック・分離水準は `linearizability` の
上に乗っていて、もともと並行と分散のものである。設計論の `read-write-separation` と
`idempotence` がこれを要求しているので、消すと辺が切れる。並行と分散の
blurb に一行足して、そちらの範囲だと書いた。

### 学習理論の連載（2026-08-28 に足し、同日に外した）

PAC 学習、VC 次元、Sauer--Shelah、no free lunch、後悔の最小化を 12 概念で
足して、`taxonomy.ts` に「学習理論 全 4 回」を立てた。**同じ日に外した。**

**理由は、中核が数学で閉じていること。** 汎化の隔たりは集中不等式、VC 次元と
Sauer--Shelah は組合せ論、一様収束は解析。確率論の応用として書けるので、
計算機の連載として立てる必要が無い。統計学として測度と確率の側に置くほうが素直。

数学で出ないのは一箇所だけだった。**標本は足りているのに、その仮説を多項式時間で
見つけられない**（`hardness-of-learning`）。ここは計算量理論だが、1 概念のために
連載は立たない。

**外向きの辺が一本も無かったので、綺麗に落ちた。** `regret-minimization` が
`online-competitive-ratio`（アルゴリズムと下界）を要求していただけで、
逆向きは無い。もう一度足すときも閉じた 12 個で済む。

**反論として一つ残しておく。情報理論も同じ性質を持っている。** あちらも中核は
確率論で、`entropy` は `expectation` を要求するだけである。それでも cs に置いて
記事を 3 本書いてある。だから「数学で閉じるから cs ではない」を一般則にすると、
情報理論も外れる。**線は「数学で閉じるか」ではなく、「計算機の側で何が導けるか」に
引くこと。** 情報理論には符号化定理と通信路容量があり、学習理論の側には
`hardness-of-learning` の 1 個しか無かった。そこが差である。

### 「記事内の参照は peek を切る」（2026-08-23 に決め、同日に撤回）

決めた理由は「謎解きは大謎の材料を忘れさせるのに、peek は常に思い出させる。
だから同じ記事の中で peek を付けるのは、忘れる余地を潰している」だった。

**実装の前に測って、前提が間違っていたことが分かった。**

peek が添えているのは 621 件で、**参照先はすべて statement**（定義・定理・命題・
補題・系・公理）である。いっぽう大謎の材料は**構造的な気づき**のほうで、
ベクトル解析 1 の「3 次元で k 形式の成分は 1, 3, 3, 1 個」は `#table` で書かれていて、
そもそも peek の対象ですらない。

**この二つは重なっていなかった。**「定義 5」を思い出させることは、大謎を殺さない。
「参照」という一語だけで二つを同一視していた——差を数えずに同一視するという、
[writing.md](writing.md) に書いたばかりの失敗そのものである。

そして距離を測ると、元の理屈（分割注意）のほうが正しかった。

| 参照元と参照先の行距離 | 件数 |
| --- | --- |
| 0〜10 行 | 61 |
| 11〜25 行 | 116 |
| 26〜60 行 | 178 |
| 61〜120 行 | 116 |
| 121 行以上 | 150 |

**71% が 25 行より遠い**（中央値 49 行、最大 1029 行）。往復コストは実在する。

さらに `peek.ts` の `asPeek` は最初から `<details>` を落としていて、
**想起の問いを参照したときに答えが漏れない配慮は既に入っていた。**

残った論点は、下の「すぐそこを指す参照には添えない」で片付けた。

## 同時に走るときの作法

- **worktree で作業するなら、本体の checkout にも `npm ci` しておく。**
  `astro check` が `Tsconfig not found astro/tsconfigs/strict` で落ちるときはこれである。
  vite（rolldown）は tsconfig を上のディレクトリまで探しに行くので、
  `.claude/worktrees/*` から見て親にあたる本体の `tsconfig.json` を拾う。
  そちらに `node_modules` が無いと、`extends` が解決できずに sync ごと止まる。
  **worktree 側の `tsconfig.json` をいじっても直らない**（`extends` を消しても同じ
  エラーが出る）。原因は隣ではなく上にある
- push の直前に必ず `git fetch origin && git rebase origin/main`
- **rebase のあとに `npm run verify` を回し直す。** 別セッションが同じファイルを
  触っている（`README.md`、`src/lib/taxonomy.ts`、`src/data/concepts.ts` が衝突しやすい）
- 相手の作業に force-push で上書きしない
- 連載の構成・本数・分野の増減を変えるときは、このファイルに一行書いてから変える
