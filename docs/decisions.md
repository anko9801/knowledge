# 決めたことと、決めていないこと

**このリポジトリは複数のセッションが同時に触る。** 2026-08-21 には push が
非 fast-forward で 5 回弾かれ、同じ連載を別々の判断で削る、という取り違えも起きた。

`docs/build.md` は**仕組みの説明**で、ここは**判断の記録**である。
なぜそう決めたか、そしてまだ決めていないことを置く。
コミットメッセージにしか無い理由は、探せないので消えたのと同じになる。

書くときは日付を付ける。撤回したものは消さず、取り消し線ではなく
「撤回」の節へ移して理由を残す。同じ議論を二度しないためにある。

## 決めていないこと

**決める前に、ここを読んでほしい。** 片方だけ直すと食い違う。

### λ 計算と Curry–Howard をどちらの連載の正典にするか

`lambda-calculus` / `simply-typed-lambda` / `curry-howard` を、
形式意味論 第 1 回（`linguistics/semantics/1`）が `provides` している。
いっぽう `cs/types`（型と計算）も同じ範囲を扱う予定で立っている。

概念グラフは複数の記事が同じ概念を provide してよい（経路の選択肢になる）ので
壊れないが、本文が二重になる。どちらかを正典にして、もう片方から参照するのが自然。

**cs 側を正典にするのが筋だと思う。** 形式意味論は λ 計算を道具として
使う側で、型理論そのものを主題にしていない。ただし cs/types をまだ書いていないので、
書く人が決めてよい。

### cs の連載本数

2026-08-21 に、情報理論を 6→3 回、計算量理論を 7→3 回へ `taxonomy.ts` の blurb を
書き換えた。**概念グラフの穴がちょうど埋まる本数に合わせただけ**で、
「これ以上書くことがない」という判断ではない。

厚く書く計画だったなら戻してよい。同じ日に別セッションが
「型と計算の 2 本を落とす」（`556f6fa`）をしており、**同じ連載を二人が別々に
削っている**。連載の長さを変えるときは、ここに一行書いてから変える。

## 決めたこと

### PDF も配る（2026-08-22）

`.typ` は最初から二つの出力を持つように書いてあった（`template.typ` の `target()`）。
paged 側に A4 の紙面まで用意しておきながら、一度も配っていなかった。

`postbuild` で 86 本を出して、記事から辿れるようにした。画面で読む以外の読み方
——印刷する、書き込む、手元に置く——は「47 秒の初回訪問」とは別の経路で、
そこに応えるものが無かった。`dist` は 27M から 47M へ増える。

**やめるなら `package.json` の `postbuild` から外すだけ。** 記事側は
リンクが 404 になるので、そのときは `[order].astro` の `.pdf` も消す。

### docs は三つに分ける（2026-08-22）

`build.md` が 1204 行あって、フォントのサブセット手順と「なぜ隙間を先に開けるか」が
同じ file に並んでいた。**記事を書く前に読むべき三節が、typst の踏んだ穴に埋もれる。**

読み手に向けた判断を `reader.md` へ移した（558 行と 676 行になった）。

| | 何が書いてあるか | いつ読むか |
| --- | --- | --- |
| build.md | 作り方。typst、Astro、フォント、踏んだ穴 | 仕組みを触るとき |
| reader.md | 読み手に何を出すか。書き出しの型、文体、想起の問い | 記事を書く前 |
| decisions.md | セッションをまたぐ決めごとと、まだ決めていないこと | 連載の構成を変える前 |

**`decisions.md` と `reader.md` は役割が違う。** こちらは日付を付けて積む記録で、
あちらは現時点の決めごとを一枚にまとめたもの。判断の理由をここに書き、
出す形を向こうに書く。

### 題名は替えず、概念名を足す（2026-08-22）

題名は異常を出す形にしてある（「穴が空いていないこと」「好きに選んだのに、
答えが整数になる」）。掴みには効くが、**何を学ぶ回なのかが題名から読めない**。
連載の一覧を眺めている読者と、検索から来た読者はそこで止まる。

題名を概念名に替えると掴みが消えるので、替えずに足した。
`provides` として既にデータにあるものを、記事の題名の下と分野の一覧に出す。
全部は出さない（多い回で 32 個）。記事で 6 件、一覧で 5 件、残りは数だけ。

### 数学の記事を、物理のために書かない（2026-08-20）

数学の連載で、物理を**導入**にも**到達点**にも置かない。本文中の例として一言だけ。

`taxonomy.ts` が math と physics を分野として分けている以上、数学の連載の
到達点が全部物理なら、その分割が嘘になる。実際、線形代数 4 の第 1 節が
「物理のテンソルはなぜどちらかに寄るのか」、Riemann 6 が記事まるごと
Einstein 方程式になっていた。

物理を外した穴には**数学側の payoff を入れる**。外して終わりにしない
（比較幾何、Mayer--Vietoris をそこに置いた）。逆向き——物理や化学の連載が
数学を前提にする——は正しい依存なので自由。

### 概念グラフを一次データにする（2026-08-21）

記事の front matter から依存グラフを生やす作りを捨てて、
`src/data/concepts.ts` を一次データにした。使い方は `docs/reader.md`。

**記事から生やすと、まだ書いていない領域がグラフに存在しない。**
だから「次に何を書くべきか」を問えない。実際、作り直したら 27 本書いた時点で
いちばん書くべきなのが「ベクトル空間」（下流 110）だと出た。

### 分野は丸ごと採らず、サブ領域で切る（2026-08-21）

化学全体は経験則だが「分子の点群と選択則」は群論から出る。
言語学全体は経験的だが「形式意味論」は型で決まる。
論理で閉じる範囲だけを `requires` に書き、残りは `empirical` に逃がす。

分野名で切ると、経験則の辺が数学側の最短経路を汚す。

### 層バッジを外した（2026-08-21、`b3259b1`）

各記事の冒頭に L0 / L1 / L2 と計量の有無を出す仕組みを入れ、57 本に付けたあと外した。
`src/typst/layer.typ` と CSS も消してある。**復活させないこと。**

理由は二つ。読者にとって自分用の分類記号でしかなく、記事のいちばん高価な場所
（書き出し）を占めていた。そして分類が持ちこたえておらず、
「L1、最後だけ L2」「L1 ＋ L2 混在」「L1 ＋ 一部 L2」と例外を書き足していた。

**例外を二つ書いたら、その分類は持っていない。** 押し通さずに疑うこと。

何を仮定した回かは、本文の中で言う。

### 書き出しは、ありえないことを先に見せる（2026-08-21、`b3259b1`）

「前回までに〜を作った」で始めない。続きものの段取りから入ると、
途中から来た読者が置いていかれる。

型は四つ。現象が先で名前は後、一見ありえない、解決は既知の材料だけ、一話完結。
詳細は `docs/build.md`。

## 同時に走るときの作法

- push の直前に必ず `git fetch origin && git rebase origin/main`
- **rebase のあとに `npm run verify` を回し直す。** 別セッションが同じファイルを
  触っている（`README.md`、`src/lib/taxonomy.ts`、`src/data/concepts.ts` が衝突しやすい）
- 相手の作業に force-push で上書きしない
- 連載の構成・本数・分野の増減を変えるときは、このファイルに一行書いてから変える
