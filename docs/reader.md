# 読み手に何を出すか

読み手に向けた判断だけを集めてある。**何を出し、何を出さないか。根拠と、外れ方と、代償。**

- どう作っているか（typst、Astro、フォント、踏んだ穴）は [build.md](build.md)
- セッションをまたぐ決めごとと、まだ決めていないことは [decisions.md](decisions.md)

**記事を書く前に「書き出しの型」「文体」「一人称をどこまで使うか」の三節を読むこと。**
読み忘れると全部やり直しになる。書き出しだけは `npm test` が機械で見る
（`src/lib/opening.test.ts`）。

## サイドバーに何を出すか

全分野・全連載・講義ノート 44 本を常に開くと、目に入る項目が 80 を超える。読み手は
自分の居場所を見失い、まだ読んでいない量に圧倒される。そこで**今いる文脈だけを開く**。
判断は `src/lib/nav-scope.ts`（純関数、テストあり）、描画は `Sidebar.astro`。

| どこにいるか | 開くもの | 畳むもの |
| --- | --- | --- |
| 連載の記事 | その連載（全 12 回など） | 同じ分野のほかの連載、ほかの分野、講義ノート |
| 分野の目次 | その分野の連載（先頭だけ開く） | ほかの分野、講義ノート |
| 講義ノート | その群（ノート / レポート） | もう一方の群、分野 |
| 入口 | 何も開かない | すべて |

畳んだものは 1 クリックで開く。**選べる道は減らさない**。順番を決めてやると迷いは
減るが、自分で進み方を決めたい読み手の意欲は削がれる（Duolingo が経路を 1 本に
固定して長年の利用者から反発を受けた例がある）。

添える情報は 3 つだけ。

- **現在地の目盛り**「第 3 回 / 全 12 回」とバー。今いる連載にだけ出す。まだ手を
  付けていない連載に 0 % のバーを並べると、未読の一覧が借金の一覧に見えて逆効果。
- **続きから** 最後に読んだ記事へ 1 手で戻る。記録は端末の localStorage だけで、
  外へは出ない。無ければ枠ごと出ない。
- **入口** 何も読んでいない人にだけ「はじめて読むなら」を 1 行。道を 1 本示して、
  並んだ選択肢の前で立ち止まらせない。入口は `taxonomy.ts` の `start: true` で
  宣言する（1 つだけ）。

読んだ記事には ✓ が付く（localStorage）。連続記録や達成率のような、完了を急かす
仕掛けは置かない。

## 47 秒と、隙間と、できるようになったこと

読者は集中して座っていない。画面ひとつに留まる時間の中央値は、2004 年に 2.5 分、
その後 75 秒、いまは **47 秒**である（Gloria Mark、別チームの再現で 44 秒・50 秒）。

先に俗説を落としておく。「集中力が 8 秒で金魚以下」は**否定されている**。短尺動画に
ついても、相関の証拠は堅いが**因果の証拠は弱く**、効果は状態的で可逆的だと読むのが
妥当である（2025 年の系統的レビュー。実験は課題復帰と抑制制御の短期的な悪化までしか
示していない）。

だから設計目標は「壊れた読者への配慮」ではない。**47 秒の初回訪問を生き延び、
再訪に報いること。** この違いは大事で、ここの読者には検索から来る専門家も混じる。

### 小さい隙間ほど強く効く

好奇心は、知識の**隙間**を感じたときに立つ（Loewenstein 1994）。ここで効くのは大きさで、
**小さい隙間ほど強い**——10 のうち 8 を知っている人は残りの 2 を強く知りたがるが、
2 しか知らない人は残りの 8 に興味を持たない。そして開けっ放しの隙間は、
やがて苛立ちに変わる。

この一本で、三つの要求が同時に説明できる。

| | 症状 | 隙間の言葉で |
| --- | --- | --- |
| 47 秒で離脱する | 問いが本文の中にあり、答えは末尾 | 隙間を開けるのが**遅い** |
| 途中から入ると楽しくない | 前提リンクが「他を 3 本読め」と言う | 隙間を**広げて**いる |
| 続ける動機が湧かない | 閉じたことが見えない | 隙間が閉じた**手応えが無い** |

打ち手も対応する。

- **冒頭を問いにする。** `summary` は「何を書いたか」であって「何が分からないままか」
  ではない。47 秒のうちに隙間が開く位置へ、問いの形で置く
- **前提に `gist` を添える。** リンクだけだと読みに行かせることになる。一行の説明を
  併記すれば、途中入場者がその場で 8/10 になる
- **読めるようになった回を返す。** 下を参照

### 動機は、報酬ではなく手応えで上がる

「動機が上がり続ける」を点数・連続記録・達成率で作ろうとすると、**必ず落ちる**。

ゲーミフィケーションのメタ分析（Sailer &amp; Homner 2020）は全体で cognitive g = .49 を
出すが、**報酬と地位の機構だけは効きが薄い**。効くのは挑戦・意味のある目標・物語の
ほうである。しかも期間で減衰する——数日で ES = 1.57、20 週で 0.30、年単位では
ES = −0.20 と符号が反転する。

理由は報酬そのものにある（Deci, Koestner &amp; Ryan 1999、128 研究）。

| | d |
| --- | --- |
| 取り組みに対する報酬 | −0.40 |
| 完了に対する報酬 | −0.36 |
| 出来に対する報酬 | −0.28 |
| **できたという手応え** | **+0.33**（興味 +0.31） |

そして自己決定理論のメタ分析（144 研究・79,000 人）では、**有能感がいちばん強い
予測因子**で、次が自律性、関係性はいちばん弱い。

**だから返すのは点数ではなく、できるようになったことにする。**

記事の末尾の「この回を前提にしている回」は、読了記録（端末の localStorage）と
突き合わせて、**前提が全部揃った回に印を付ける**。見出しも「ここまでで、次が
読めるようになった」に変わる。判定は `prerequisites`（`neighbors.ts`）で、
表示用の `requires` と違って**一つも落とさない**——落とすと、前の回を読んでいない
人にも揃って見えてしまう。

置かないものは、いままでどおり。

- **数えない。** 何本読んだか、何 % 進んだかは出さない。出すのは「いま何が読めるか」
  だけで、それは借金の一覧ではなく行き先の一覧である
- **祝わない。** 印は矢印ひとつ。演出を足すと報酬の側に寄る
- **初回の読者には出さない。** 読んだ記事が 1 本しか無いうちは、ただの下流の一覧のまま

読むほど前提が埋まって読める回が増えるので、これは**実際に単調に増える**。
作った気分ではなく、グラフ上の事実を返しているだけである。

### 書き出しの型：異常を先に出す

隙間を 47 秒以内に開ける、いちばん確実な形は**ありえないことを先に見せる**ことである。
ドラマの『ガリレオ』の作りがこれで、燃える頭や光る海が先に出て、
既知の物理だけで解かれる。新しい魔法は使わない。

数学でもそのまま使える。むしろこちらのほうが持ち駒が多い。

```
= 確率 0 のことが、必ず起きる

[0,1] にダーツを投げる。ちょうど 0.5 に刺さる確率は 0 である。
0.3 でも 0、1/π でも 0。どの一点についても 0 である。
それでもダーツはどこかに刺さる。
```

型は五つ。

1. **現象が先、名前が後。** 用語を一つも出さずに、起きることだけを書く
2. **一見ありえない。** 読者の持っている模型と衝突していること。衝突しないなら
   隙間が開かない
3. **解決は既知の材料だけ。** その回で新しく持ち出す道具で解いてはいけない。
   前回までに通った道で解けるから、途中入場の読者にも閉じる
4. **一話完結。** 開けた隙間は、その回の中で閉じる。連載の最後まで開けっ放しに
   しない（開いたままの隙間は苛立ちに変わる）
5. **強い素材を到達点にしない。** 異常は入口であって、商品ではない。
   下を参照

3 と 4 が、そのまま「途中から読み始めても楽しい」の条件になっている。

### 異常は入口であって、商品ではない

強い素材には、それ自体が面白すぎて**構成をサボらせる**という副作用がある。
掴みが強いと、そこで満足して記事がその謎の解説で終わる。

だから開けた隙間は、**記事の中盤で閉じる。** 閉じたあと、そこで買った注意を
読者が来た理由とは別のところで使う。位置は前でよく、前に出さないのは
「位置」ではなく「点」のほうである。

- 悪い ── ダーツの謎 → 零集合で解決 → 「この読み替えが今回のすべてである」
- よい ── ダーツの謎 → 零集合で解決 → **同じ読み替えが、最後には
  「σ 加法族が、どこまで知っているかを表す」まで行く**

読者は「確率 $0$ なのに起きる」を知りたくて来て、
条件付き期待値が直交射影であることを持って帰る。これが飛躍である。

**飛躍を修辞で通さない。** 知識エンタメでは、無理のある接続を大まじめな語り口で
押し切るのが定石だが、ここでは使えない。辺が本物であること
（`requires` と `empirical` を分け、mathlib で検算する）がこのサイトの前提なので、
言い張って通した接続は前提のほうを壊す。

代わりに使えるものがある。**定理である。** 数学の飛躍は、修辞ではなく証明が
着地を保証してくれるので、補助装置が要らない。

| 入口 | 出口 | 通した定理 |
| --- | --- | --- |
| 公式が多すぎて覚えられない | 三つの積分定理は一つ | 一般化された Stokes |
| 微分方程式が解けるか数える | 位相が出る | de Rham |
| 計量で積分したのに計量が消える | 曲率の総和が位相不変量 | Gauss--Bonnet |

**接続に定理が付かないなら、その飛躍は書かない。** そこは `empirical` の辺と
同じ扱いで、書きたければ「経験的にそう言われる」と断ってから書く。

**「前回、〜」で始めない。** 続きものの段取りから入ると、途中入場の読者は
2/10 の状態に置かれ、隙間が大きすぎて好奇心が立たない。前回の話は、
異常を出したあとで持ち出せばよい。

かつて **17 本**がこの形だった（`= ` の直後が「前回」「ここまで」「道具は」など）。
**いまは 0 本。** 直すのは 1 本ずつの手作業だが、戻るのは一瞬なので
`src/lib/opening.test.ts` で止めてある。`npm test` が拾う。

最後に直した 7 本を、入口として何を出したかと一緒に置いておく。

| 記事 | 出した異常 |
| --- | --- |
| 土台 第 4 回 | 同じ形なのに、片方にだけ穴がある |
| ベクトル解析 第 3 回 | 二つの公式が、どちらも 0 になる |
| 群と表現 第 2 回 | ほとんど捨てても、何も失われない |
| 群と表現 第 4 回 | 好きに選んだのに、答えが整数になる |
| 微分形式 第 8 回 | 材料を共有しない二つの数え方が、同じ答えを出す |
| Riemann 幾何 第 8 回 | 足元だけ見て、果てまで分かる |
| 量子力学 第 2 回 | 当たり前のことを二つ言うと、選択肢が消える |

### 出典について

**この節と「想起の問い」の数字は、原論文を読んで確かめたものではない。**
メタ分析の要約と二次資料から取っている。効果量の桁と符号、モデレータの向きは
複数の資料で一致しているので設計の根拠には使えるが、小数第 2 位まで引くときは
原論文に当たること。とくに次の三つは、資料の側が食い違っていた。

- ゲーミフィケーションの効果量は、資料によって g = .49 から g = .82 まで開く。
  異質性が極端に大きい（ある higher-ed のメタ分析で I² = 98.8%）ので、
  **プールした数字自体があまり意味を持たない**。効くのは要素別の内訳のほう
- 期間による減衰は、期間と設計・場面・脱落が交絡している。
  「新奇性が切れる」は**もっともらしい解釈であって、示された因果ではない**
- segmenting の効果量は、Mayer 自身の章では中央値 0.79 だが、メタ分析
  （Rey et al. 2019）では g ≈ 0.32〜0.36。**ここでは低いほうを採った**

### 文体：読者の躓きを名指しする

[EMAN の物理学](https://eman-physics.net/) を参考にしている。ただし**まねる層を
間違えないこと。**

まず外すところから。**文末ではない。** EMAN も「である」を使う
（「これを『保存力』と呼ぶのである」）。この repo の文末を変える必要は無い。
差は*何を書くか*にある。

借りるのは三つ。

- **読者の躓きを名指しして、先に否定する。** これが本体である。原文は
  「知らないというのは立場が弱い」のように、読者が抱く感情を代弁してから進む
- **思考過程を開示する。** 結論だけでなく、なぜその定義になるかを追体験させる
- **教科書が省く隙間を書く。** 「ここは自明」で飛ばされるところを、実際に書く

一つ目の型を、実例で置いておく。

```
悪い ── 単に主張する
  これは Skolem のパラドックスと呼ばれるが、矛盾ではない。

よい ── 疑いを先に言葉にしてから否定する
  初めて聞いたとき、どこかに間違いがあると思うのが普通だと思う。
  対角線論法が壊れたのか、前回の構成に穴があるのか、と。
  どちらも壊れていない。
```

```
悪い ── 不便さを黙って通す
  この体系で φ → φ を導くには数行が必要になる。

よい ── 読者が自分を疑うところを、先に止める
  ここで多くの人が、自分の理解を疑う。こんな簡単なことが書けないのは、
  どこかを読み落としたからではないか、と。読み落としてはいない。
```

**取らないものが三つある。**

- **句読点の `,` `.`。** EMAN の目立つ癖だが、ここの和文組版
  （`text-spacing-trim`、`word-break: auto-phrase`、約物の詰め）は全角約物を
  前提にしている。入れると組版が崩れる
- **権威を茶化す口調。** 検索から来る専門家が同じページを見る。
  そして `CLAUDE.md` がキャラクターを記事に持ち込むことを禁じている
- **社会的な動機づけ**（「知らないと立場が弱い」）。このサイトは構造から動機を
  作る建て付けなので、ここを借りると本体と衝突する

### 一人称をどこまで使うか

`CLAUDE.md` は「なぜ私がその名前を選んだかは、読者に関係がない」と書いている。
一方で上の型は「私もそう思っていた」を推奨する。矛盾ではない。**線はここにある。**

| 書かない | 書く |
| --- | --- |
| 著者の編集判断（命名の経緯、構成の都合） | 読者も同じところで躓く、という事実 |
| 会話で到達した結論の、議論の形 | その主張を初めて見たときの、自然な疑い |
| 「〜と呼びたくなるが」 | 「初めて読むと、証明を追えても納得できない」 |

判定は簡単で、**その一文を消したら読者が困るか**を見る。困るなら躓きの共有、
困らないなら著者の事情である。

### 正直な代償

記事を短く割ること（segmenting）は、注意には効くが**万能ではない**。メタ分析
（Rey et al. 2019、56 研究・88 比較）で g ≈ 0.32〜0.36 の小〜中で、しかも
**総学習時間はむしろ増える**。「短くすれば早く終わる」ではない。境界条件も
教科書の記述とは逆に出ていて、**前提知識が高い読者ほど恩恵が大きかった**。

## 概念から引く

記事は連載として順に並んでいる。だが**検索から来る読者は語で来る。**
「σ 加法族」を調べに来た人に、測度と確率 第 1 回の全文を渡すのは遠回りである。

そこで概念ごとに索引のページを置く（`/concepts/<id>`、283 ページ）。出すのは 4 つだけ。

| | |
| --- | --- |
| 何か | `gist` の一行 |
| どこで読めるか | その概念を扱っている回へのリンク |
| これを読むのに要るもの | `requires` |
| これを使うもの | 逆向きの辺 |

**解説はここに書かない。記事が本体で、これは索引である。** グラフを front page に
据えた先例（Metacademy）は、グラフ自体が商品だったので手入れが止まった時点で
残るものが無かった。ここでは概念ページから記事へ送るのが仕事で、
それ以上の中身を持たせない。

**記事のある概念だけを出す。** 記事の無い概念にページを与えても、読者はそこから
何もできない。既存の判断（下流は記事があるものだけ）に揃えてある。
`neighbors.ts` の下流と同じで、未執筆は執筆キューであって読者向けではない。

検索の並びは狙いどおりになった。語で引くと概念ページが先に出て、そこから記事へ送る。

```
"σ 加法族" → /concepts/sigma-algebra → /math/measure/1 → …
"測度"     → /concepts/measure       → /math/measure/1 → /math/measure/3 → …
```

日本語の数学サイトでいちばん大きい「高校数学の美しい物語」は、
**1 記事完結**にして検索着地に強くしている（1000 本、月 470 万 PV）。
こちらは連載を崩さずに、索引のほうで同じ入口を作った。

## 手助けはすべて任意にする

前提リンク・参照に添えた中身・想起の問いは、どれも**読者が取りに行かないと何も
起きない**形にしてある。これは趣味ではなく、外し方が分かっているからである。

手助けは、前提を持たない読者には効き、**既に知っている読者には害になる**。
既知の情報を照合させるぶんが余計な負荷になるためで、熟達の逆転（expertise reversal）
と呼ばれる。2025 年のメタ分析は 60 研究・176 の効果量・5,924 名を集めていて、
**要素の絡み合いが多い題材ほど強く出る**——数学はまさにそれである。

このサイトの読者は、集合論から順に読む人から、検索で 1 本だけ来る専門家まで幅がある。
どちらへ転ぶか事前に分からない。そこで**押し付けず、取りに行けるようにする**。

- **前提**は 1 行。要らなければ目に入って終わる
- **参照に添えた中身**はホバーするか取っ手を押すまで出ない。知っている人は触らない
- **想起の問い**は畳んである。飛ばしても本文の筋は通る

逆向きの非対称もある。手助けを与えないことで熟達者が得るものより、**与えることで
初学者が得るもののほうが大きい**（Kalyuga らの再解析）。迷ったら出す側に倒す。
ただし**押し付けない形で**。

## 記事のページに前提と下流を出す

連載の前後（第 2 回の次は第 3 回）は**編集上の並び**でしかない。読者が知りたいのは
論理的な前後——「この回を読むのに何が要るか」「この回はどこで効くか」——で、それは
概念グラフが持っている。記事は `provides` を名乗るだけなので、辺はページ側で引ける。
判断は `src/lib/neighbors.ts`（純関数、テストあり）。

| どこ | 何を出すか |
| --- | --- |
| 表題の下 | **前提**。読む前に、自分が読める状態かを判断させる |
| 前後ナビの下 | **この回を前提にしている回**。読んだ後に、どこで効くかを示す |

検索から 1 本だけ飛んできた読者は、いま自分がその回を読めるのか判断できない。
前提が出れば判断できる。下流が出れば、読む理由が後から立つ。

**前提は直接の `requires` だけを見る。** 推移的に遡ると集合論まで戻ってしまい、
「この回の直前に要るもの」という問いに答えられなくなる。実測で平均 2.3 件、最大 6 件。

**概念単位のままだと同じ記事が何度も並ぶ。**「確率空間」と「条件付き期待値」で
測度と確率 第 3 回が 2 回出る。記事ごとに畳んで、理由の概念を添える形にする。

```
前提  第 3 回 — k 形式・楔積   第 2 回 — 引き戻し   第 1 回 — ベクトル場・Lie 括弧
```

**一つの概念に家が複数ある。** Stokes の定理はベクトル解析（$\mathbb{R}^3$）にも
微分形式（一般）にもあり、楔積は線形代数・ベクトル解析・微分形式の三つにある。
どれも間違いではなく、扱う一般性が違うだけである。そこで**読者にいちばん近い扱いへ
送る**。今いる連載に家があればそこへ、無ければ `taxonomy.ts` の宣言順で手前にある
いちばん近い連載へ。手前に一つも無いときだけ先へ送る。

だから `taxonomy.ts` の `series` は、**素朴な扱いから一般的な扱いへ**並べておくこと。
宣言順を入れ替えると、前提リンクの行き先が動く。いま重なっているのは 11 概念で、
すべて 線形代数 → ベクトル解析 → 微分形式 → Riemann 幾何 の鎖の上にある。

出し方の判断は 3 つ。

- **記事の無い前提は「未執筆」と出す。** リンクはしない。穴の場所を隠さない
- **下流は記事があるものだけ。** 未執筆の下流を出しても読者は何もできない。
  それは執筆キューであって、読者向けの情報ではない
- **前後ナビにすぐ出るものは落とす。** 同じリンクが二度出るだけになる
  （`neighborsOf` の `exclude`）

### 概念の名前にも、数式が書ける

概念の `label` と `gist` は `src/data/concepts.ts`、つまり TypeScript の中にある。
長らく**数式を書けない場所**だった。組む経路が Typst 側にしか無いからで、
`H^*_dR` のような書き方を決めて、表示のときに正規表現で肩へ乗せていた。

engine が二つある状態なので、`H^*` は組めても分数や積分は組めない。しかも
索引のように**名前だけが並ぶ場所**では、`b_k = dim H^k` がそのまま見えていた。

いまは **Typst の記法をそのまま書く**。

```ts
c('betti-numbers', 'Betti 数', '$b_k = dim H^k$。穴の個数', ...)
c('lp-space', '$L^p$ 空間', '可測関数の空間。完備になる', ...)
```

`$...$` を含むものだけを 1 枚の文書へ並べて**ビルド中に 1 度だけ** compile し、
出てきた MathML を引き戻す（`concept-typst.ts` が組み立てと切り分け、
`concept-math.ts` が typst の起動）。記事と同じ font、同じ組版になる。

**HTML を置けない場所には `plainMath()` を通す。** 名前順に並べる鍵、`title`、
読み上げの `aria-label` の三つで、`arrow.r.bar` を `↦` に均した文字列が要る。
均す表は**実際に書いてあるものだけ**にしてある。Typst の記号表を写し取ると、
本体と食い違ったときに気づけない。

## 想起の問い

定着するのは読んだ瞬間ではなく、**取り出そうとした瞬間**である。だから本文の中に、
答えを畳んだ問いを置く。

想起の効果はメタ分析で繰り返し確かめられている（Rowland 2014 で g = 0.50、
Adesope 2017 で g = 0.61、教室での実測でも Yang 2021 が g = 0.50）。
このサイトに効くのは、そこから先の二つである。

- **応答の一致**が効き目を倍にする。Pan &amp; Rickard 2018（192 の効果量）では、
  練習と本番で作る答えの形が違うと d = 0.28、揃うと d = 0.58。
  ここでの「本番」は将来その概念を使うときなので、問いは**言明ではなく筋道**を
  作らせる形にする
- **膨らませた想起**が d = 0.23 上乗せする。単なる再生ではなく、説明を組ませる
  問い（Bloom の上の段）のほうが転移する

だから問いは軽くしない。1 問 6 秒に収めるのは間隔反復（Quantum Country は 112 問を
5〜7 巡させる）の設計で、読みながら 1 度だけ通る問いとは経済が違う。

**思い出せるかではなく、区別が付いているかを突く。**「σ 加法族の定義は」では
なく「位相は任意個の合併で閉じるのに、σ 加法族が可算個までなのはなぜか」。
前者は再認で、後者は再生である。

### 問いは、対比のあるところにしか無い

**探す場所が決まっている。** 60 問あまり書いて分かったことを書いておく。

良い問いが出るのは、本文が**すでに何かを対比している**節である。
そうでない節からは、どれだけ粘っても出てこない。

| 何と何を対比しているか | どこ |
| --- | --- |
| 1 点と場 | 微分形式 2（接ベクトルは送れるが、場は送れない） |
| 位相と距離 | 土台 4（同相なのに片方だけ完備） |
| 関数とベクトル場 | Riemann 幾何 2（片方だけテンソルになる） |
| 状態と装置 | 量子力学 2（不確定性の証明に測定が出てこない） |
| 規約と観測量 | ベクトル解析 1（右ねじを替えても物理は動かない） |
| 掛け算と足し算 | 情報理論 1（だから log が出る） |
| 有限と無限 | 集合論 5（有限なら選択公理は要らない） |
| 内包原理と分出 | 集合論 1（同じ論法が、片方は体系を壊す） |

理由は単純で、**答えが「どちらか」で書ける**からである。対比が無い節では、
問いが「何だったか」にしかならず、再認に落ちる。

だから使い方は逆向きにもなる。**問いが書けない節は、対比を持っていない。**
書けるかどうかが、その節が何を主張しているのかを測る道具になる。
淡々と積み上げているだけなら、問いを足すより本文のほうを見直す合図である。

### 記憶とは別の効き目

読み手が次に何を読むかを自分で決めるサイトでは、**自己評価が当たるかどうか**が
記憶と同じくらい効く。外れていれば、分かっていない回を分かったことにして先へ進む。

そして再読で生じる滑らかさは、理解と取り違えられる（Wiley et al. 2005）。
ただし「分かった感覚がまるで当てにならない」わけではない。学習判断と実際の再生の
順位相関は 1 回目で γ ≈ 0.41 程度——**中くらいに当たる**。効くのはその
次で、**一度テストを受けると 2 回目は γ ≈ 0.62 まで上がる**
（Nelson &amp; Dunlosky 1991 系列の実験）。

つまり問いは、覚えさせるだけでなく**読者の見積もりを較正する**。
連載を先へ進むかどうかの判断が、そのぶん当たるようになる。

```typst
#check[問い][答え]
```

`theorem.typ` の `check`。題名を渡すとそれが見出しになる。

```typst
#check[問い][答え]                     見出しは「問」
#check("前回のふりかえり")[問い][答え]    見出しは題名のほう
```

**番号は振らない。** 参照されない番号はドリルの体裁を足すだけで、
定義と定理の通し番号に穴が空いたようにも見える。見出しの言葉も、
設計の語彙（想起、較正）ではなく読者の言葉で書く（`CLAUDE.md`）。

答えは `<details>` なので **JS が要らない**。
CSS が落ちても開いた状態で読めるし、印刷（PDF）では「答え．」として並ぶ。

置き方は 3 つ。

| どこに置くか | 何を狙うか |
| --- | --- |
| 節の切れ目、答えを述べた直後 | 想起。読み流した箇所を止める |
| 記事の冒頭（第 2 回以降） | 間隔をあけた復習。前回の主題を 1 問だけ |
| 主張の直後、証明の前 | 方針を立ててから読ませる |

**採点も記録もしない。** 正解・不正解を数えない、連続記録を出さない、未回答を
残さない。サイドバーの方針（完了を急かす仕掛けは置かない）と同じである。
問いは読み飛ばしてよく、飛ばしても本文の筋は通る——答えは本文に書いてあるので、
`check` は本文の要約であって、新しい情報を持ち込まない。

いまは **63 問**。全 17 連載に行き渡り、記事 89 本のうち 48 本に置いてある。
1 回あたり 1〜3 問で、密度は揃えていない。
上の表のとおり、置ける場所が節の性質で決まるからである。
全記事に一斉に入れるものではない。問いを書くコストが本体で、
機械的に足すと「答えが本文にある」条件がすぐ崩れる。

数字の目安として、Quantum Country（問いを本文に埋めた先例）は**読む時間が 35〜50%
増える**と報告している。そして本文の問いを解き終えた読者のうち、1 か月後の復習まで
届いたのは 29%。あちらは全問必答を前提にした設計で、こちらは読み飛ばしてよい設計
なので、そのまま比べられる数字ではない。ただ**問いを置けば読む時間は確実に増える**
という側だけは同じなので、密度を上げるときはそこを見込むこと。

## 参照の先を、その場に出す

`@def:measure` は Typst が `<a href="#loc-1">定義 5</a>` として出す。押すと定義まで
飛ぶが、読者は読んでいた場所を失い、スクロールで戻ることになる。定義を思い出す
たびに往復が入り、作業記憶がそこに食われる（分割注意）。

そこで**参照点に、指す先の中身をそのまま添える**。ホバーと `:focus-within` で開く
ので **JS は要らない**（4 本のまま）。
中身を差し込むのは `src/lib/peek.ts`（ビルド時、純関数、テストあり）。

負荷の出どころは**リンクそのものではなく、たどるかどうかの判断**である
（DeStefano &amp; LeFevre 2007）。埋め込みリンクのある文書は素の文書より負荷が高く、
リンクが多いほど、また意味的に遠いほど悪く、**作業記憶と前提知識が少ない読者ほど
損をする**。添えて出せば、その判断が要らなくなる。

同じ形の仕掛けを大規模に配ったのは Wikipedia の Page Previews で、展開後にページ
ビューが 3.0〜4.7% 落ちた。**飛ばずに済ませた分**であって、失敗ではない。切る人は
0.02〜0.03% しかいなかった。

### 触るだけの端末には、取っ手を置く

ホバーの無い端末では、この仕掛けが**まるごと届いていなかった**。押す = リンクを
たどるなので、開いた瞬間に画面が変わり、添えた中身を読む機会が無い。
読者の大半がそちらにいるので、いちばん効くはずの相手に効いていなかったことになる。

そこで参照の後ろに小さな取っ手（`▾`）を置き、checkbox で開く。
**JS は増やさない**——骨格の開閉と同じ手である。

| | 開き方 | 出方 |
| --- | --- | --- |
| ホバーできる端末 | ホバー、`:focus-within` | 浮かせたパネル（従来どおり） |
| 触るだけの端末 | 取っ手を押す | その場に開いて、下を押し下げる |

**浮かせない**のがこちらの要点で、浮かせると本文を覆い、開いた分だけ読んでいた行が
隠れる。押し下げれば、読んでいた行はそのまま上に残る。

**リンクは残す。** 取っ手が増えるだけなので、読み上げにも、主張まで飛ぶ従来の道にも
影響しない。押し付けず取りに行かせる形（上の「手助けはすべて任意にする」）も保てる。

出し分けは `@media not all and (hover: hover) and (pointer: fine)`。
ホバー側の否定にしてあるので、**両方が当たることがない**。取っ手の押せる範囲は
`padding` で約 44px 角にし、負の上下余白で行の高さは変えていない。

`id` は参照ごとの通し番号で振る（`peek.ts` が `pk`、`page-peek.ts` が `pp`）。
錨から作ると、**同じ主張を二度指したときに重複して**どの取っ手も最初の一つを開く。
前者は loader、後者は `[order].astro` と走る場所が違うので、接頭辞で分けてある。

### 引くのは理解のためで、覚えるためではない

即座に出せば、思い出す手間が消える。手間の側にこそ長期の定着があるので
（Bjork の retrieval strength と storage strength）、添えることは**記憶には効かない
どころか逆を向く**。この二つは狙いが違うと割り切ってある。

- **参照に添える**のは、いま読んでいる証明を追い切るため（理解）
- **想起の問い**は、後で使えるようにするため（定着）

だから `peek.ts` は `check` の `<details>` を落とす。答えを添えてしまうと、
残っているほうの狙いまで消える。

ホバーしてから開くまで **300ms 置いてある**。文字の上を通っただけで開くのを防ぐのが
主で（Wikipedia も「うっかりホバー」を測る前提で滞留時間を置いている）、
思い出そうとする隙をわずかに残す意味もある。

添えるのは**主張だけ**。式番号や見出しへの参照はそのまま通す。添えても「式 3」が
「式 3」に見えるだけで、往復の手間が減らない。

## 置かないもの

**練習問題を置かない。** 技能を付けるなら、解答例 → 穴あき → 自力（fading、
Renkl &amp; Atkinson 系列）が最も確からしい形で、この連載にはそれが無い。
欠けているのではなく、**扱っていることが違う**。ここで書いているのは
「定義がなぜその形なのか」で、計算が速くなることではない。想起の問いが聞くのも、
解けるかではなく区別が付いているかである。

技能まで扱うことにしたら、`check` を足すのではなく fading の系列を別に立てること。
問いの形が違うので、同じ枠には収まらない。

**概念グラフを主役にしない。** 依存グラフを front page に据えた先例に Metacademy
（2014、概念 487・辺 1208）がある。よくできていたが、**グラフそのものが商品だった**
ため、手入れが止まった時点で残るものが無かった。いまは更新の止まったまま、
無関係な SEO スパムが混ざっている。

ここでは**記事が本体で、グラフは道具**である。執筆計画を立て、前提リンクを引く。
グラフの更新が止まっても、記事は記事として残る。順序を逆にしないこと。

## 概念グラフと執筆計画

一次データは `src/data/concepts.ts` の**概念グラフ**である。記事があるかどうかとは
無関係に「何を理解するには何が要るか」だけを書く。記事はそこへの被覆でしかない。

**記事から生やしたグラフでは計画が立たない。** まだ書いていない領域がグラフに存在しない
ので、「次に何を書くべきか」を問えない。だから概念を先に置く。被覆されていない概念が
そのまま執筆キューになり、依存順に並ぶ。

```sh
npm run curriculum stats            # 概念数、被覆率、循環、ずれ
npm run curriculum goals            # 到達目標と、そこまでの残り本数
npm run curriculum plan stokes      # 依存順。記事の有無つき
npm run curriculum next 10          # 次に書くべき記事（下流の多い順）
npm run curriculum gaps             # 記事の無い概念すべて
npm run curriculum dump             # JSON
```

記事側の front matter は `provides` だけを見る。前提は概念グラフが持つので、
記事に書く必要がない。`requires` / `uses` も置けるが、いまは使っていない。

### 辺は 2 種類

| | 意味 | 既定でたどるか |
| --- | --- | --- |
| `requires` | **論理的**。定義に現れるか、証明が引用する。文献で確かめられる | たどる |
| `empirical` | **経験的**。分野の慣行として必要だが、論理的必然ではない | たどらない |

「この順で教わるのが普通だから」という慣習は、どちらにも書かない。シラバスから吸える
前提はほとんど慣習で、遠回りの正体もそこにある。混ぜた時点で、最短経路が既存の
カリキュラムをなぞるだけのものになる。

`empirical` を分けてあるのは、医学や生物学のように経験則が本体の分野を、数学側の
経路を汚さずに載せるためである。`plan --empirical` で明示的に辿ったときだけ現れ、
その概念には `~`（経験的）の印が付く。

**分野を丸ごと採らず、サブ領域で切る。**「化学」全体は経験的だが「分子の点群と選択則」
は群論から導ける。「言語学」は経験的だが「形式意味論」は型付き λ 計算で決まる。
どこまでが論理で決まるかを見極めて、そこだけを `requires` で書く。

### 依存が明示される分野

| 分野 | 依存が現れる形 |
| --- | --- |
| 数学・論理 | 証明が補題を引用する |
| 計算量理論 | **還元** $A \le_p B$。主張そのものが依存 |
| 暗号理論 | **安全性の帰着**。「仮定が破れないなら安全」 |
| 型理論 | Curry--Howard。型が命題 |
| 情報理論 | 符号化定理が確率論から出る |

### mathlib から取ってくる

形式化された数学のライブラリは、依存がコンパイラに検証された形で存在する。

```sh
node scripts/mathlib-graph.mjs Geometry   # モジュール 145 / 辺 449
```

取れるのはモジュール単位の依存で、定理単位ではない。定理単位は doc-gen4 の生成物か、
ローカルに Lean を入れて `#print axioms` を回す必要がある。

モジュール単位でも使い道がある。`Mathlib.Geometry` の外部依存は Analysis 76、
Topology 39、Algebra 24、LinearAlgebra 11 で、**手で書いたグラフが解析を軽く見ている**
ことが分かった。指摘に従って解析の 13 概念を足したところ、執筆キューの先頭が
「滑らかさの階層」（下流 75）に変わった。手書きを検算する道具として実際に効く。

```sh
node scripts/mathlib-compare.mjs mathlib-*.json   # 概念グラフと突き合わせる
```

### 粒度は畳めるか

畳めない、というのが答えである。6 分野 3652 モジュールと概念 263 を名前で突き合わせると、
数学の概念のうち対応が付いたのは **31%** にとどまる。そして内訳に理由が出ている。

| 概念の種類 | 対応が付いた | 付かなかった |
| --- | --- | --- |
| `definition` | 49 | 65 |
| `theorem` | 5 | 49 |
| `technique` | 5 | 10 |
| `viewpoint` | **0** | **9** |

`definition` は当たる。mathlib はファイル名を、そこで定義する対象から付けるからである。
`theorem` は当たらない。定理はファイルの中にあって、名前に出ない。
そして `viewpoint`——「基底の選択」「行列表示」「自然な同型」「写像の不変量」——は
**一つも当たらない**。mathlib は数学を形式化しているのであって、教え方を形式化していない。

つまり mathlib は**定義の層は供給できるが、見方の層は供給できない**。
そして教材の依存グラフを形式化のそれと分けているのは、まさに見方の層である。

使い道は次の二つに限る。

- **検算**。こちらの辺が mathlib の import に無ければ、依存を書き間違えている疑いがある
- **抜けの検出**。`Mathlib.Topology.Order` 44 本、`Mathlib.Probability.Distributions` 25 本など、
  こちらの概念が一つも触れていない塊が 27 個・計 381 本ある

`next` は「前提がすべて記事になっている」ものを先に出し、下流の概念数が多い順に並べる。
前提が揃っていないものを書いても、読者が読めないからである。

`stats` の `循環` は概念グラフの書き間違いを、
`グラフに無い概念を記事が名乗っている` は語彙のずれを検出する。どちらも 0 に保つこと。
